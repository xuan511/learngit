# SnapMind 架构

这是原生 Qt Widgets 桌面程序，没有 WebView、服务端、账号或联网 OCR。

模块边界：

- `app.py`：高 DPI 初始化、可写便携目录、单实例锁与启动。
- `ui.py` / `style.py`：导航、首页、分页检索、编辑器、快捷面板、设置、统一 SVG 图标及深浅主题。
- `capture.py`：每显示器独立选区窗口，逻辑坐标换算到各自屏幕原始像素；预览、标注、撤销重做。
- `native.py`：Windows `RegisterHotKey`、原生消息分发、前台进程查询；不模拟键盘粘贴。
- `services.py`：剪贴板 MIME 快照与自复制标记、图片与 PDF 导入、惰性加载 RapidOCR。
- `jobs.py`：一个串行 IO 队列、一个独立串行 OCR 队列。OCR 的 ONNX CPU 推理限制为 2 个内部线程。
- `store.py`：独立短连接、WAL、外键、FTS5 触发器、备份恢复与附件引用保护。
- `paths.py`：相对附件路径、可写目录验证、原子设置文件。

数据保存在程序目录 `data/`。`SNAPMIND_HOME` 或 `--data-dir` 可以指定其他便携根目录，程序不保存开发机绝对路径。外部文件链接是用户选择的绝对路径，迁移时需要重新定位；托管图片和 PDF 随数据一起迁移。

数据库 schema v1：`records` 保存内容、原始 OCR、修正文、标签、MIME HTML、收藏与时间；`links` 保存笔记到截图 / PDF / 其他记录的有向关联与页码；`records_fts` 和三个触发器保持索引一致。未来版本必须先备份再执行递增迁移；当前版本拒绝打开更高版本数据库。

检索同时查询 FTS5 和转义后的 `LIKE`，多关键词取交集，中文子串、单汉字、寄存器片段可检索。零精确结果时，对最近最多 1000 条候选做英文词近似匹配，列表明确标记“近似匹配”。近似匹配不是全库编辑距离搜索；短于 4 字符的查询不做近似匹配，避免数值和寄存器地址被误判。筛选支持类型、标签、收藏和日期，结果每页最多 60 条。

写入 OCR 时在事务中重新检查正文，避免推理期间的手工修正被覆盖。编辑器按改动字段自动保存，修改标题不会用旧正文覆盖后台识别结果。原始 OCR 不做技术内容自动纠错。

备份用 SQLite 在线备份 API 获取一致的数据库副本，再收集其引用的附件。恢复先在临时目录校验路径、版本、完整性和附件，之后替换数据目录，保留恢复前副本。恢复时暂停捕获并停用内容区域。退出等待已运行的后台写入完成。日志不记录剪贴板明文。

Windows 全局热键仅使用注册 API，注册冲突会保留原绑定并提示修改。黑名单依据复制时的前台可执行文件；查询失败时有黑名单配置则跳过捕获。应用内复制携带随机 MIME 标记，处理同步及延迟的自身剪贴板通知。

发布为 PyInstaller onedir 目录，Qt 动态库独立可替换，ONNX 模型位于 `_internal/`，许可证在顶层 `licenses/`。运行时不下载模型。构建前及首次加载时核对三个模型的 SHA-256，清单来自固定版本 wheel 的安装产物。OpenCV 与 ONNX 均限制为 2 个计算线程，关闭 OpenCL 及 ONNX 遥测。
